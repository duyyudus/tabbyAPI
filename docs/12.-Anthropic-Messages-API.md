# Anthropic Messages API

TabbyAPI exposes `POST /v1/messages` and `POST /v1/messages/count_tokens`, a stateless
implementation of the Anthropic Messages protocol for local models. It is enabled with
the OAI server (`api_servers: ["OAI"]`) and uses the same API keys: send the key as
`x-api-key` or `Authorization: Bearer`. The loaded model needs a chat template and, for
tools, a supported tool format.

## Claude Code

Point Claude Code at the server and name the loaded model for every model slot, including
the one used for background tasks:

```bash
export ANTHROPIC_BASE_URL="http://localhost:5000"
export ANTHROPIC_API_KEY="YOUR_TABBY_API_KEY"
export ANTHROPIC_MODEL="YOUR_LOADED_MODEL"
export ANTHROPIC_DEFAULT_OPUS_MODEL="YOUR_LOADED_MODEL"
export ANTHROPIC_DEFAULT_SONNET_MODEL="YOUR_LOADED_MODEL"
export ANTHROPIC_DEFAULT_HAIKU_MODEL="YOUR_LOADED_MODEL"
claude
```

With `inline_model_loading: false` (the default), requests always run on the loaded model
whatever name they carry. With inline loading enabled and an admin key, a name that is not
in the model directory fails with `not_found_error`, so set the model variables above.

Recommended settings:

- `CLAUDE_CODE_MAX_OUTPUT_TOKENS`: a limit that fits your context length; Claude Code's
  default output budget is sized for hosted models.
- `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS=1` and `DISABLE_NONESSENTIAL_TRAFFIC=1`: optional;
  beta fields are ignored here anyway.

### Model discovery

With `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1`, Claude Code reads `GET /v1/models` at
startup and adds models to its `/model` picker. It only reads each entry's `id`, but it
keeps only IDs that contain `claude` or `anthropic`, so local model names are filtered out.
Advertise a dummy model name that passes the filter:

```yaml
model:
  use_dummy_models: true
  dummy_model_names: ["claude-local"]
```

Requests that name a dummy model run on the loaded model and never trigger an inline load.
Dummy names are also listed to OpenAI clients. Discovery is optional; the model variables
above work without it.

Claude Code prepends an attribution block to the system prompt. As on the first-party API,
it is dropped when it arrives as the first `system` block, so it does not change the prompt
or defeat the prefix cache.

## Python SDK

```python
import anthropic

client = anthropic.Anthropic(base_url="http://localhost:5000", api_key="YOUR_TABBY_API_KEY")
with client.messages.stream(
    model="YOUR_LOADED_MODEL",
    max_tokens=1024,
    thinking={"type": "adaptive"},
    messages=[{"role": "user", "content": "Explain how a hash table works."}],
) as stream:
    for text in stream.text_stream:
        print(text, end="")
```

## Supported parameters

| Capability | Behavior |
| --- | --- |
| `model` | Existing model selection and inline-loading policy; responses report the loaded model's name |
| `max_tokens` | Required, at least 1; the limit includes thinking and tool call tokens |
| `messages` | `user`, `assistant`, and `system` turns; consecutive turns of one role are merged. A leading `system` turn joins the system prompt; later ones become user-turn text, because chat templates reject system messages mid-conversation |
| `system` | String or text blocks, joined with blank lines |
| Final `assistant` turn | Prefill: generation continues the text. Trailing whitespace is rejected, as on the first-party API |
| `stream` | Anthropic SSE events (`message_start`, `content_block_*`, `message_delta`, `message_stop`); keep-alive pings are `ping` events |
| `temperature`, `top_p`, `top_k`, `stop_sequences` | Mapped to sampling settings; `stop_reason` is `stop_sequence` only for a requested sequence |
| `tools` | Custom tools with `input_schema`; `strict: true` validates generated input against the schema. Anthropic-hosted tools (`web_search_*`, `bash_*`, ...) are accepted, ignored, and never shown to the model |
| `tool_choice` | `auto`, `any`, `tool`, `none`; `disable_parallel_tool_use` keeps only the first call. A forced choice is an instruction to the model, not a guarantee |
| `thinking` | `enabled` and `adaptive` set the `enable_thinking` template variable; `enabled.budget_tokens` sets the reasoning budget. `disabled` or absent turns thinking off and removes any reasoning from the output. `display: "omitted"` returns empty thinking blocks |
| `output_config.effort` | Forwarded as `reasoning_effort`; `xhigh` and `max` become `high` |
| `output_config.format` | JSON schema constrained output; cannot be combined with tools |
| Content blocks | `text`, `image` (base64 or URL, vision models only), `document` (plain text or content sources), `search_result`, `thinking`, `redacted_thinking` (dropped), `tool_use`, `tool_result` |
| Hosted-tool blocks | `server_tool_use`, `*_tool_result`, `tool_reference`, and `container_upload` are dropped from replayed history |
| `cache_control`, `metadata`, `service_tier`, `context_management`, other unknown fields | Accepted and ignored; prefix caching is automatic |

Replayed thinking blocks are passed to the template as `reasoning_content`. Signatures on
generated thinking blocks are opaque and never verified.

## Responses

A `tool_use` stop streams each call as one `input_json_delta` once the call is complete:
calls are parsed only after generation ends, so text generated after a call is delivered
after it too. On a `max_tokens` stop, a partial tool call is never returned.

`usage.input_tokens` excludes the prompt tokens served from the cache, which are reported
in `cache_read_input_tokens`; `cache_creation_input_tokens` is always 0. In the stream,
`message_start` reports the full prompt and `message_delta` carries the final split.

## Errors

Errors use the Anthropic shape, `{"type": "error", "error": {"type": ..., "message": ...}}`:

| Status | `error.type` | Cause |
| --- | --- | --- |
| 400 | `invalid_request_error` | Validation, messages naming the field such as `messages.0.content.0.text: Field required`; an oversized prompt reports `prompt is too long: ...`, which Claude Code offers to compact |
| 401 | `authentication_error` | Missing or invalid API key |
| 404 | `not_found_error` | Requested model is missing while inline loading is enabled |
| 500 | `api_error` | Generation failed, or the model produced an unparseable tool call |
| 503 | `api_error` | No model is loaded |

An error after streaming has started is sent as an `error` event.
